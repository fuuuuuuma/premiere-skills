# テロップ校正 (/telop-check)

書き出し済みMP4のテロップ（焼き込み済みキャプション・タイトルカード）を全編スキャンし、
「本来アラビア数字であるべき箇所が漢数字になっている」「誤字脱字」「い抜き言葉」
「ら抜き言葉」「固有名詞のミス」を検出し、タイムコード付きの一覧で報告する。

**検出専任。動画は書き換えない。** 焼き込み済みのMP4を直接編集する手段がないため、
出力は「誤→正」の一覧のみ。実際の修正は元のPremiere Proプロジェクト側で行う。

## 使い方

```
/telop-check /path/to/video.mp4
```

クライアントからの修正指示（例:「0分14秒→百万を100万に変更」等）が手元にある場合は、
同じメッセージに続けて貼り付ける。指示があれば、そのパターンを最優先の手がかりとして
動画全体に同じ規則を適用する。指示がなくても `references/telop_check_rules.md` の
既定ルールだけで検出は動く。

長尺（20分超）の場合は `--stride 2` のように間引きを指定できる:

```
/telop-check /path/to/video.mp4 --stride 2
```

## 手順

### Step 0: 事前確認

- 入力パスの存在確認（`ffprobe` で長さ・解像度を取得。開けない場合はここで止めて報告）
- 出力先 `output/telop-check/<basename>/` を用意する（`<basename>` は拡張子を除いたファイル名）
- 動画が20分（1200秒）を超える場合、`--stride` 未指定なら「`--stride 2`推奨」と一言添えてから既定値のまま進める（止めない）

### Step 1: コンタクトシート生成

```bash
python3 scripts/telop_frames.py "<video>" --out "output/telop-check/<basename>/frames" [--stride N]
```

標準出力の `manifest.json` パスと `grid_count` を控える。`grid_count` が想定よりかなり多い
（60枚超）場合はスクリプト側の警告が出るので、そのままユーザーに伝えてよい（自動で
`--stride` を変えて再実行はしない。動画の長さは変えられないため、判断はユーザーに委ねる）。

### Step 2: 並読 — 画面文字の書き起こし（並列Agent）

`manifest.json` の `grid_files` を4枚ずつのグループに分け、グループごとに1体の
Agent を **同じメッセージ内で並列起動**する（`model: sonnet`）。Workflow機構は使わない
（`/srt-fast` v7.1 と同じ判断: オーケストレーション自体がオーバーヘッドになる規模の作業ではない）。

各Agentへの指示:

- 割り当てられた各グリッド画像を `Read` で読む。1枚に16コマ（4x4）敷き詰められており、
  各コマ左上の黄色いラベルがそのコマの実秒（動画開始からの経過秒）
- 画面に映っている**編集側が追加した文字要素**（下部テロップ・タイトルカード・図解グラフィック内の文字）を、
  見えたまま一字一句正確に書き起こす。要約・言い換え・整形はしない
- **除外する**: ブラウザ・Xの投稿・スプレッドシート・他アプリなど「画面録画/スクリーンショットとして映り込んでいるだけの文字」。編集側が直接書き換えられる要素ではないため対象外（`references/telop_check_rules.md` §0）
- 同じ文言が連続するコマに渡って表示されている場合、**最初に現れた秒だけ**を記録する
- 出力形式: `{seconds, text}` の配列（1体につき最大数十件程度になる想定）

### Step 3: 集約

全Agentの出力を1本のタイムラインにマージし、`seconds` 昇順に並べる。文言が完全一致し
かつ近接（目安30秒以内）する重複エントリは、最初の1件だけ残して間引く（同じテロップが
離れた時間に再掲される場合はそのまま両方残してよい。次段の検出Agentが判断する）。

### Step 4: 固有名詞辞書の収集（あれば）

以下を順に試し、見つかったものだけ使う（無ければ静かにスキップ。エラーにしない）:

1. `config/corrections.local.json` を読む
2. `config/channel_profile.md` の固有名詞欄を読む
3. Premiere Proのパネルが接続されていれば `premiere_dictionary(op: "list")` を呼ぶ

### Step 5: 検出（並列Agent）

Step 3 のタイムラインを60件程度ずつのチャンクに分け、チャンクごとに1体のAgentを
並列起動する（`model: sonnet`）。各Agentへの指示:

- `references/telop_check_rules.md` の全ルールを読んで適用する（§1〜5が判定基準の正典）
- ユーザーから修正指示が渡されていれば、その具体例を最優先のパターンとして扱う
- Step 4 で集めた固有名詞辞書を渡し、辞書に反する表記だけを「固有名詞」種別で検出する（辞書に無い語は検出しない）
- 1エントリにつき0件以上の指摘を `{timestamp(mm:ss), wrong, correct, category, severity, note}` で返す
  - `category`: 数字表記 / 誤字脱字 / い抜き / ら抜き / 固有名詞
  - `severity`: 要修正（数字表記・誤字脱字・固有名詞）/ 要確認（い抜き・ら抜き）
- い抜き・ら抜きは §3・§4 の判定条件（統一度／活用型）を必ず適用してから報告する。条件を満たさない場合は報告しない

### Step 6: 統合・出力

- 全Agentの指摘を `timestamp` 昇順にマージ
- 同一文言の再掲がある場合は初出行にまとめ、「(以降 X:XX 等にも同じ表記が再掲)」を注記する（`references/telop_check_rules.md` §7）
- `output/telop-check/<basename>/report.md` に `references/telop_check_rules.md` §7 の表形式で書き出す
- ユーザーへの応答にも同じ表をそのまま貼る。検出0件のカテゴリも「検出なし」と明記する
- 末尾に一言添える: 「このMP4は書き出し済みのため自動修正はできません。上記を元のPremiere Proプロジェクトで修正してください」

### Step 7: 後片付け

`output/telop-check/<basename>/frames/` 配下の `grid_*.png` を削除する（`manifest.json` は
残してよい）。数百枚のPNGを `output/` に残さない。

## 固有名詞辞書への追記（任意）

Step 5 で「固有名詞ミスの可能性があるが辞書に登録がない」語が見つかり、ユーザーが
正しい表記を教えてくれた場合は、承認を得たうえで `config/corrections.local.json` に
`{"誤表記": "正表記"}` を追記してよい（次回以降の `/telop-check` と `/srt-fast` の両方に効く）。

## やらないこと

- 動画・音声ファイルの書き換え（焼き込み済みテロップは対象にできない）
- Premiere Proプロジェクト（XML等）への書き戻し（`references/telop_check_rules.md` §6 参照。未実装・将来課題）
- い抜き・ら抜きを「必ず直すべき誤り」として断定すること（口語スタイルの可能性があるため常に「要確認」に留める）
