# SRT 絶対ルール（ハード制約）+ ソフト制約

このファイルは `/srt` の Step 5（LLM 改行テキスト生成）で参照する。

## 絶対ルール（ハード制約）

### 1. LLM 分割判断を機械で代替禁止
fugashi / MeCab / Ginza / ルールベースは**候補抽出の補助**としてのみ使用可。最終判断は必ず LLM が全文を読んで行う。`should_emit_between()` のような品詞ベース emit 判定関数を Python で書くのは禁止。

### 2. 複合動詞句の分断絶対禁止
以下は 1 つの動詞句として扱う:
- 「〜ている」「〜ていく」「〜てくる」「〜てみる」「〜ておく」「〜てしまう」
- 「〜てほしい」「〜てくれる」「〜てあげる」「〜てもらう」「〜てやる」
- 「〜てもいい」「〜てはいけない」「〜てこそ」「〜ておかない」
- 「〜ている所」「〜ていこう」「〜ていかない」等の派生形も含む

### 3. 単独で意味が通じる単位にする
各テロップを**単独で読んで視聴者が内容を把握できるか**チェック。「いるので」「ことに」のような連結フラグメントは不可。

### 4. 文頭フラグメント禁止
以下で始まるテロップは作らない。発生したら必ず前のテロップと統合:
- 助詞単独: 「か」「も」「を」「に」「が」「は」「の」「と」「や」「ね」「よ」「ぞ」
- 「で」(接続詞「でも」「です」「では」以外の単独「で」)
- 動詞活用語尾: 「ます」「まし」「ません」「でした」「きます」「きる」「きれ」「きない」
- 否定: 「ない」「なく」「なっ」
- 連体接続: 「という」「として」「について」「によって」
- 抽象名詞: 「ため」「とき」「はず」「こと」「もの」+ 助詞
- カタカナ破片: 「ベル」「ース」「トル」「ション」「ング」「タイ」「ティ」等

### 5. 固有名詞・カタカナ語・英数字の分断禁止
「[CHANNEL]」「MiniMax Audio」「ElevenLabs」「LINE登録」「VOICEVOX」「レベル」等は一体。

### 6. 「た + 連体修飾名詞」の分断禁止
「〜た + こと/もの/とき/はず/ため」のパターンは連体修飾句として 1 単位扱い。例:
- ✗ 「AIの音声だった / ことに気づきました」
- ✓ 「AIの音声だったことに気づきました」

### 7. 「ということで/は/です」の分断禁止
「と+いう+こと+で/は/です」は複合終止表現として一体。

## ソフト制約

| 項目 | 目安 | 備考 |
|---|---|---|
| 文字数 | 4〜25字 | 意味優先。4字でも OK、26字以上は要分割 |
| 表示時間 | 0.8〜3.5秒 | 自動で最小800ms保証 |
| 文字/秒 | 5〜10 | 早口すぎず遅すぎず |
| 行数 | 1 行 | 改行なし。話者ポーズは半角スペース |
